# cn2an

Subset port of the Python [cn2an](https://github.com/Ailln/cn2an) 0.5.24
package, for the GPT-SoVITS text frontend. GPT-SoVITS calls
`cn2an.transform(text, "an2cn")` in `chinese.py`, `chinese2.py` and
`cantonese.py`.

## Ported

| Python | Rust |
|---|---|
| `cn2an.transform` (`Transform().transform`) | `cn2an::transform` |
| `cn2an.an2cn` (`An2Cn().an2cn`) | `cn2an::an2cn` |
| `cn2an.transform.Transform`: `transform` with `method="an2cn"` (with and without `direct`), `__sub_util` for the an2cn sub modes (`range`, `date`, `fraction`, `percent`, `celsius`, `number`, `direct`), `measure_words`, `direct_an_pattern` | `cn2an::transform::Transform` |
| `cn2an.an2cn.An2Cn`: `an2cn` in all modes (`low`, `up`, `rmb`, `direct`), `__direct_convert`, `__check_inputs_is_valid`, `__integer_convert`, `__decimal_convert` | `cn2an::an2cn::An2Cn` |
| `cn2an.conf`: `NUMBER_LOW_AN2CN`, `NUMBER_UP_AN2CN`, `UNIT_LOW_ORDER_AN2CN`, `UNIT_UP_ORDER_AN2CN` | `cn2an::conf` |
| `proces.preprocess` (proces 0.1.7, a cn2an dependency): `preprocess`, `traditional_to_simplified`, `full_angle_to_half_angle` | `cn2an::proces::preprocess` |

The an2cn path of `transform` does not call `Cn2An`, so no part of
`cn2an/cn2an.py` is ported.

Data:

- `data/t2s.tsv`: proces `T2S_DICT` (a Python dict literal), converted by
  `parity/export_data.py`.
- `data/python_decimal_ranges.txt`: the code points that Python 3.11 `re`
  matches with `\d` (Unicode 14.0 decimal digits), exported by the same
  script. The transform patterns use `\d`, so text with Arabic-Indic,
  Devanagari or full-width digits matches as in Python. Full-width digits are
  then converted by `full_angle_to_half_angle`; other non-ASCII digits make
  `An2Cn.an2cn` raise, and `__sub_util` returns the match unchanged.

Implementation notes:

- The regular expressions are hand-written matchers (`src/transform.rs`), one
  per Python pattern, each documented with the pattern it replaces. The
  patterns are deterministic, so trying each start position in order and
  taking the greedy match gives the same matches as Python `re.sub`.
- Python exceptions become `cn2an::Error::ValueError`. Python `int()`
  failures and the unpacking errors in `__sub_util` also map to `ValueError`.
  Messages are close to the Python text but are not part of the parity
  contract.

## Left out

- `transform(..., method="cn2an")` and all of `Cn2An` (`cn2an.cn2an`). Returns
  `Error::NotPorted`.
- `An2Cn.an2cn` with `int`/`float`/`None` inputs (`__number_to_string`). The
  Rust API takes `&str`; an empty string gives the same error as `None`.
- `warnings.warn` calls (decimal parts longer than 16 digits, caught
  exceptions in `__sub_util`). The behaviour is ported, the warnings are not
  emitted.
- The other `proces` pipelines (`filter_unusual_characters`,
  `handle_blank_character`, `uppercase_to_lowercase`, `handle_substitute`),
  `params`, list inputs, and `proces.masking`. `preprocess` returns
  `Error::NotPorted` for those pipeline names.
- `cn2an.utils` (logging and YAML config helpers), `performance.py` and the
  test modules.

## Parity

Fixtures are generated by `parity/generate_fixtures.py` and
checked by `tests/parity.rs`:

| Fixture | Cases | Exact matches |
|---|---|---|
| `transform_an2cn.jsonl` (`transform(x, "an2cn")`) | 6390 | 6390 |
| `transform_an2cn_direct.jsonl` (`transform(x, "an2cn", direct=True)`) | 1598 | 1598 |
| `an2cn.jsonl` (`An2Cn().an2cn(x, mode)` for 4 modes, including errors) | 1811 inputs × 4 modes = 7244 | 7244 |

Inputs combine hand-written edge cases with random samples (fixed seeds):
integers of 1 to 20 digits with uniform, zero-heavy and 0/1 digit
distributions, decimals with up to 20 fraction digits, negatives,
percentages, fractions, dates in several formats, temperatures, ranges with
every measure word, Unicode digits (full-width, Arabic-Indic, Devanagari,
mathematical, and Unicode 15 Kawi digits that Python 3.11 does not treat as
`\d`), and mixed Chinese/Latin/punctuation sentences.

There are no known mismatches.

`traditional_to_simplified` has no observable effect on outputs: no
`T2S_DICT` key or value is one of `0123456789.-`, and `An2Cn` rejects every
other character after preprocessing. It is ported for fidelity, and the
fixtures cannot distinguish it from a no-op.

The Python reference environment is the crate-local pixi workspace in
`pixi.toml` (Python 3.11, cn2an 0.5.24, proces 0.1.7). Regenerate from the
repository root with:

```sh
pixi run --manifest-path crates/ports/cn2an/pixi.toml data
pixi run --manifest-path crates/ports/cn2an/pixi.toml fixtures
```

See `parity/README.md` for details.
